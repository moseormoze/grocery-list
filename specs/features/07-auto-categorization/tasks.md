# Tasks: סיווג אוטומטי לפריטי סופר

סטטוס: הבריף, זיכרון התיקונים, איכות ניסוי Claude והסוויש הקוסמי אושרו ב-2026-11-16. המשתמש אישר להשלים את כל המשימות ברצף בהודעת ״יאללה תסיים הכל כבר״. T1–T4 מומשו מקומית, עם בדיקות לפני מימוש. אימות DB חי ופריסה עדיין נדרשים. הפירוק מחליף לחלוטין את משימות המילון המקומי.

## Technical Approach

- ספק ומודל: Claude, `claude-haiku-5-5`, עם הפרומפט והפלט המובנה שנבדקו ב-T0. אין סבב שיפור דיוק נוסף כתנאי למימוש. אי-התאמה לציפיית סיווג אינה זהה לתקלת שמירה.
- סדר הקדימות: בחירה ידנית בפעולה הנוכחית, העדפת הבית, מטמון AI של הבית, בקשת Claude, fallback ל-`other`. כשל בשירות AI מאפשר fallback. כשל בזיכרון או בשמירת הפריט מוצג כשגיאת שמירה.
- המפתח נקרא רק בשרת מ-`ANTHROPIC_API_KEY`. לא מוסיפים סוד עם קידומת `NEXT_PUBLIC_` ולא שולחים ל-Claude מזהי משתמש או בית. אין שינויי קטגוריות, מילון, חיפוש סמנטי או העדפות רטרואקטיביות.
- השמירה מקבלת כוונה מפורשת: `auto`, `manual` או `preserve`. בעריכה ללא שינוי בורר משתמשים ב-`preserve`, שמותיר את הקטגוריה הנוכחית ב-DB ואינו מלמד העדפה. בחירה אוטומטית אינה מוחקת העדפה.
- `auto` לעולם אינו נשמר כקטגוריה. מקור התוצאה מוחזר בנפרד לשימוש במשוב: `manual`, `remembered`, `cache`, `ai`, `fallback` או `preserved`.
- נקודת קצה אחת לסופר מטפלת בהרשאה, סיווג ושמירה ומחזירה את הפריט שנשמר בפועל. קריאות רשת ו-AI אינן מתבצעות בזמן render, הקלדה או Realtime.

### זיכרון ושמירה

- טבלה חדשה `household_item_categorizations`, ייחודית לפי `(household_id, normalized_name)`. שדות נפרדים ל-`manual_section_id` ול-`ai_section_id`, עם גרסת מודל ופרומפט למטמון. `other` מותר כהעדפה ידנית, אך אינו נשמר כתוצאת AI במטמון.
- אין שימוש ב-`categorizations_cache` הציבורית הקיימת לזיכרון או למטמון החדש. אין backfill מהטבלה הישנה.
- מקור הנרמול הסמכותי הוא פונקציית DB אחת: הסרת רווחים בקצוות ואיחוד רצפי whitespace, כולל טאבים ושורות חדשות. אותו מפתח משמש בקריאה ובשמירה. אין שינוי בשם המוצג, בהבדלי טעם, בגרשיים או באותיות לטיניות.
- RLS לקריאת נתוני הבית בלבד. כתיבה לטבלה החדשה דרך RPC מבוקר, לא ישירות מהלקוח. ההעדפות אינן נמחקות במחיקת פריט, רשימה או סיום קנייה, ורק מחיקת הבית מוחקת אותן.
- `save_supermarket_item` שומר את הפריט ואת ההעדפה הידנית באותה טרנזקציה. כל כשל מבטל את שניהם. ב-`auto` הוא בודק שוב את העדפת הבית לפני קביעת הקטגוריה הסופית.
- השמירות לאותו בית ושם מנורמל מסודרות באמצעות נעילה ברמת טרנזקציה, גם כשאין עדיין רשומת זיכרון. בחירה ידנית שהושלמה לפני השמירה האוטומטית גוברת על תשובת AI שהתעכבה. בחירה ידנית שהושלמה אחריה משפיעה על הוספות עתידיות בלבד.
- אין החזקת נעילת DB בזמן בקשת Claude. אין הסתמכות על timestamps שמגיעים מהמכשיר.
- RPC שפועל כ-`security definer` חייב `search_path` קבוע, שמות טבלאות מלאים, הרשאת execute למשתמש מחובר בלבד ובדיקה מפורשת של `auth.uid()`, חברות בבית, סוג הרשימה ושייכות הפריט לרשימה. הבית נגזר מהרשימה ולא ממה שהלקוח טוען.
- בעריכת פריט נשמרים מזהה היוצר, מצב הסימון והסדר. פריט שנמחק בזמן ההמתנה אינו נוצר מחדש. מפתח קטגוריה לא חוקי, שם ריק או mode לא חוקי נדחים לפני כתיבה.

- בכל משימה: בדיקה נכשלת תחילה, בדיקות ממוקדות, TypeScript, lint וסוויטה מלאה. בסיום חיבור הממשק גם build. אין הרחבה לחוב טכני שאינו קשור ללא החלטה נפרדת.
- מצב T0 שנמדד: 12 בדיקות הכלי עוברות. הסוויטה הכוללת: 153 עוברות ו-12 נכשלות שהיו קיימות לפניו, ב-offline queue וב-sync. TypeScript נכשל בייבוא OfflineQueue קיים. `npm run lint` מבקש הגדרה ראשונית, lint ממוקד לקבצי הניסוי עבר. אלו מדידות קודמות, לא בדיקות שהורצו מחדש בעת כתיבת הפירוק.
- T0 עדיין אינו ממוזג. במהלך המימוש הרציף תוקנו חסמי הבדיקה המצומצמים: ייצוא OfflineQueue שכבר נבדק בבדיקות, תיקון שרשרת mock בבדיקת sync, והוספת תצורת ESLint. לא שונתה לוגיקת האופליין. תוצאות עדכניות מופיעות ב-`implementation-results.md`.
- יצירת ענף נחסמה שוב. השינויים נשמרו בקבצים בהתאם לבקשת המשתמש להשלים את העבודה, ללא פעולות כתיבה ב-Git. לפני commit מקומי אפשר ליצור ענף עם `git switch -c feature/07-auto-categorization/implementation`.
- בדיקות SQL דורשות PostgreSQL מבודד עם roles ו-auth context תואמי Supabase. אם אינו זמין, יש להכין בדיקות ניתנות להרצה ולדווח על החסם. לא מסתפקים בבדיקת מחרוזות SQL כדי לאשר זיכרון והרשאות.
- בדיקות אינטגרציה חיות ייעשו בסביבת בדיקה. אין החלפת המפתח הקיים, חשיפתו או הוצאות API לצורך חזרה על הניסוי שכבר התקבל.
- הבדיקות מבדילות בין שמירה שנכשלה בוודאות לבין ניתוק אחרי commit בשרת. שליחה כפולה חסומה בטופס, אך אין כאן הבטחת exactly-once בניתוק עמום או תמיכה חדשה באופליין.
- הפעלת המיגרציה והגדרת המפתח בשרת נחוצות לפני פריסה. סיום קוד מקומי אינו מוכיח שהפיצ׳ר פעיל באפליקציה המפורסמת.
