# Design System

v0 / the chosen design tool owns the detailed visual palette. This file captures decisions at the system level.

## Foundations
- **Locale**: Hebrew-first, **RTL** everywhere (`dir="rtl"` on `<html>`)
- **Theme**: TBD — defer to design tool
- **Viewport**: Mobile-first, 375px reference width
- **Feel**: Minimal, thumb-friendly, fast — a couple uses this in the supermarket aisle
- **Font**: TBD — must include a full Hebrew set. Candidates: Rubik, Heebo, Assistant, Noto Sans Hebrew.
- **Radii**: `rounded-xl` on cards, `rounded-full` on pills and chips
- **Spacing**: Generous padding — no cramped layouts
- **Tap targets**: Minimum 44px height (one-handed use in a store)

## RTL Rules
- All layout primitives must respect logical properties (`ms-`, `me-`, `ps-`, `pe-`) — never `ml-`/`mr-`.
- Directional icons (back arrow, chevrons, send) mirror in RTL.
- Numbers stay LTR inside RTL paragraphs — verify mixed-direction lines.
- Form inputs default to `dir="auto"` so users can type either language.

## Component Library
- Base: `shadcn/ui` (configured for RTL)
- Framework: Next.js + Tailwind
- Initial scaffold: generated by v0 (with RTL config) — lives in `app/` and `components/`

## Patterns
- **Primary view**: a single list, large rows, easy to tap on the move
- **Add item**: persistent input or sticky bottom sheet — decided in first Design phase
- **Check-off feedback**: visible animation (strike-through / fade) so both partners see what changed
- **Empty / loading / error**: each screen defines its own state illustrations
- **Realtime indicators**: subtle cue when partner is editing (decision deferred)

## Color Decisions (delegated)
Colors are chosen by the design tool. This repo does not prescribe hex values — trust the design tool's judgment.

## Micro-interactions (carry-over rule)
Every UI change ships with: loading state, feedback animation, and state cleanup. No "snap-in" changes without transition.
